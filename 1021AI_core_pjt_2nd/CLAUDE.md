## 0. 함께 일하는 방식 (중요)

- 사용자는 **코딩 초보**다. 개발자 친구처럼 **친근한 반말**로, 개념은 비유를 들어 쉽게 설명한다.
- 코드 주석과 출력 메시지는 **한국어**로, 초보가 읽어도 이해되게 쓴다.
- 코드를 바꾸면 **무엇을, 왜** 바꿨는지 짧게 설명하고 요구사항 번호(F2001, NF2003 등)와 연결한다.
- 실행 결과의 숫자(건수, 비율 등)는 **설계문서·검증 자료로 쓸 수 있게** 표로 정리해 준다.
- 화면 캡처가 필요한 검증 항목은 실행 명령과 함께 캡처하라고 알려준다. (명세서 4장)
- 문제가 생기면 고친 뒤 **"문제 → 원인 → 해결"** 형태로 정리해 준다 (설계문서에 그대로 씀).
- 사용자가 "바로 가자"라고 하면 확인 질문 없이 진행한다. 이미 끝난 단계를 다시 말하면 짧게 알려주고 다음 단계를 묻는다.

### 환경 주의사항
- 가상환경 폴더 이름은 **`venv`** (`.venv` 아님). 실행: `./venv/Scripts/python.exe`
- Windows 콘솔 한글: Bash에서 파이썬 실행 시 `PYTHONIOENCODING=utf-8`을 앞에 붙인다.
- Git 저장소 아님 (git init 안 함).
- 진짜 `.env`·`chroma_db/`는 테스트로 지우거나 덮어쓰지 않는다. 안내 화면 검증은 환경변수로 우회 (아래 7장).
- Streamlit 미리보기: `.claude/launch.json` 에 `streamlit`(8501) / `streamlit-test`(8502) / `test-no-key`(8503) / `test-no-index`(8504).
  사용자가 직접 8501을 쓸 수 있으니 내 테스트는 8502 이상에서 하고, 끝나면 서버를 끈다.

## 1. 프로젝트 개요

- **과제**: RAG 기반 도메인 지식 서비스
- **도메인**: **화가** (모든 국적, 한국어 위키백과 문서가 있는 화가)
- **기술 스택**: Python 3.12, LangChain, LangGraph, ChromaDB, Streamlit, OpenAI(SSAFY GMS 경유) — 버전은 명세서 지정값 (`requirements.txt`)
- **핵심 구조**: 컬렉션 2개 · RAG 프롬프트 3개 · LangGraph 노드 2개
  - 컬렉션 1 `painter_meta`: 화가 메타데이터 (화가 1명 = 청크 1개, 청크 ID = 위키데이터 ID)
  - 컬렉션 2 `painter_wiki`: 한국어 위키백과 문서 청크 (청크 ID = `화가ID:문서ID:순번`)
  - 프롬프트 1 검색어 추출 / 2 후보 문서 선별 / 3 근거 기반 답변 (+ 서비스 기능용 프롬프트 3개)
  - LangGraph: `retrieve` → `generate`

### 도메인 선택 조건 충족 근거 (요구사항 정의서용)
- 항목 메타데이터: Wikidata에서 수집, **1,343명** (조건: 약 100건 이상)
- 외부 문서: 한국어 위키백과 (CC BY-SA 4.0). 모든 화가가 한국어 문서를 가짐 (수집 조건)
- 메타데이터 출처: Wikidata (CC0 1.0)
- 근거가 필요한 질문 예시 (실제로 검증한 것):
  - "모네의 수련 연작은 몇 점이고 어디 있어?" → 약 250점, 오랑주리 8점 등 (위키 문서 근거)
  - "피카소의 게르니카는 어떤 사건을 그린 거야?" → 1937 게르니카 폭격, 사상자 수
  - "게르니카는 지금 어느 미술관에 있고 크기는?" → 레이나 소피아, 349.3×776.6cm
  - "김홍도 단원 풍속도첩에는 어떤 그림이 있어?" → 25점 목록
- 위험 도메인 아님 → 면책 문구 불필요 (F2012)

### 실행 명령 모음
```
python index_meta.py                         # F2002 메타데이터 색인 (두 번 실행해도 1,343)
python index_meta.py --search "인상주의 풍경화가"
python -m collector.query_extractor --painter "파블로 피카소" --question "게르니카는 어떤 사건을 그린 거야?"   # F2003
python -m collector.collect_docs   --painter "파블로 피카소" --question "게르니카는 어떤 사건을 그린 거야?"   # F2004 (두 번 → 캐시)
python index_wiki.py                         # F2005
python index_wiki.py --search "게르니카는 어떤 사건을 그린 거야?" --painter "피카소"
python -m rag.graph --show-graph             # F2007 그래프 구조
python -m rag.graph --painter "클로드 모네" --question "수련 연작은 몇 점이고 어디 있어?"   # F2006~F2008 (--no-collect 가능)
python -m services.painter_search "19세기 프랑스 인상주의 풍경화가"                       # F2011
python -m services.compare --a "김홍도" --b "신윤복" --focus "풍속화의 소재와 분위기"       # F2010
streamlit run app.py                         # 화면
```

## 5. 문제 → 원인 → 해결 기록 (설계문서용)

1. **[수집] 비화가 혼입**: 위키데이터 직업에 부업도 포함 → 한국어 소개 '화가'(만화가 제외)·영어 'painter'·사조 중 하나 필수 → 2,054 → 1,343명
2. **[F2002] 벡터 검색만으로 조건 검색 실패**: "인상주의 풍경화가" → 명나라 화가 1위 (주신 0.347 vs 모네 0.154). 대표작 줄여도 거의 동일 → 짧고 빈약한 텍스트가 짧은 질의와 닮아 보이는 문제 → F2011에서 필터+LLM 검증으로 해결
3. **[환경] GMS 주소 오류**: `.env`에 `/v1/chat/completions`까지 넣음 → 라이브러리가 경로를 덧붙여 실패 → `/v1`까지로 수정 + config에서 자동 정리
4. **[F2003] 너무 넓은 검색어**("20세기", 엉뚱한 "초현실주의") + 예시가 모네라 베낄 위험 → 넓은 검색어 금지, 예시를 고흐로 교체 → 이번엔 "스페인 내전"까지 빠짐 → "세기·연대는 빼고 구체적 사건 이름은 넣어라"로 명확화

6. **[F2004] 프롬프트 1·2 기준 불일치**: 1은 "6.25 전쟁"을 뽑는데 2가 일반 문서라며 버림 → 2에도 "사건을 묻는 질문이면 그 사건 대표 문서는 선택, 개별 인물·부대 문서는 제외"
