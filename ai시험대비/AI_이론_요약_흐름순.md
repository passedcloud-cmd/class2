# Part 1. AI & 기계학습

## 1-1. 지도학습의 출발점 🎯(참함수와 측정오차, 지도학습의 목적)

**데이터 = 미지의 참 함수 + 측정 오차** → `y = f(x) + ε`

- 우리는 진짜 `f`를 모름. 데이터로 `f`를 **근사**하는 게 학습이야
- 오차항 ε은 아무리 좋은 모델이라도 못 없애는 **줄일 수 없는 오차**
- **가설 공간**: 후보가 될 수 있는 함수들의 집합 (예: 모든 직선)
- **손실함수**: 예측이 얼마나 틀렸는지 재는 자

**지도학습의 목적:** (입력 x, 정답 y) 쌍으로 학습해서 **처음 보는 입력에도 맞게 예측(일반화)** 하는 것

| 지도학습 유형 | 출력 | 예시 알고리즘 | 대표 손실 |
|---|---|---|---|
| **회귀** 🎯 | 연속 숫자 | 선형 회귀 | MSE |
| **분류** 🎯 | 범주(이진/다중) | 로지스틱 회귀 | 교차 엔트로피 |

## 1-2. 선형 회귀 🎯(회귀식과 오차항, 회귀 문제, 선형회귀 계수 해석)

### ① 단순 선형 회귀 (독립변수 1개)
- `y = β₀ + β₁x + ε`
- **잔차(residual)** = 실제값 - 예측값
- **최소제곱법(LSM)**: **잔차제곱합(RSS)을 최소화**하는 β를 찾음
  - 푸는 방법 2가지: **정규방정식**(공식으로 한 번에) / **경사하강법**(반복해서 조금씩)

### ② 결과표 읽는 법
| 항목 | 의미 | 좋은 쪽 |
|---|---|---|
| Coefficient (계수) | x가 1 늘 때 y 변화량 | - |
| Std. Error (표준오차) | 표본마다 계수가 흔들리는 정도 | 작을수록 |
| t-statistic | 계수가 0에서 표준오차 몇 배만큼 떨어졌나 | 클수록 |
| **p-value** 🎯 | 귀무가설("효과 없다")이 참일 때 이 정도 결과가 나올 확률 | **작을수록 (< 0.05면 유의)** |
| **R²** 🎯 | `1 - RSS/TSS` = y의 분산 중 모델이 설명하는 비율 | 1에 가까울수록 |

- **R²**: 완벽한 모델 = 1. 단위가 사라지는 지표라서 **서로 다른 모델끼리 비교 가능**
- ⚠️ **R²는 평가 지표지 손실함수가 아니야.** 유의성 검정도 아니야 (그건 p-value·t값의 역할). 필기의 "회귀의 손실함수를 측정할 때 사용", "유의성 검정 - R²"는 고쳐 둬
- ⚠️ **계수가 0.0001처럼 작아도 p-value < 0.05면 유의해.** 계수 크기는 단위에 따라 달라지니까 유의성은 p-value로 판단해

### ③ 다중 선형 회귀 (독립변수 여러 개)
- `y = β₀ + β₁x₁ + β₂x₂ + ... + ε`. 똑같이 RSS 최소화로 추정
- **계수 해석:** β₁ = **다른 변수를 모두 고정한 상태에서** x₁이 1 늘 때 y의 평균 변화량

### ④ 다중공선성 🎯(상관관계와 다중공선성)
- **독립변수끼리 강하게 상관된 상태** (예: 키(cm)와 키(inch)를 둘 다 넣음)
- 문제: 정보가 겹쳐서 **각 변수의 고유 효과를 분리 못 함** → 계수가 불안정해지고 표준오차가 커짐
- 대응: 겹치는 변수 제거, PCA로 합치기, 규제(Ridge) 사용

### ⑤ 상관관계 🎯
- 상관계수 **-1 ~ 1**. +1이면 같이 증가, -1이면 반대로 움직이고, 0이면 선형 관계가 없어
- ⚠️ **상관관계 ≠ 인과관계**

## 1-3. 선형 회귀의 한계 → 로지스틱 회귀 🎯(분류 문제)

**선형 회귀로 분류하면 생기는 문제:** 출력이 0~1을 벗어나고, 이상치에 민감하고, 다중 분류를 못 해

**해결:** 선형식 결과를 **시그모이드에 통과시켜 0~1 확률로** 바꿈

```
z = β₀ + β₁x          (선형 결합, -∞ ~ +∞)
p = sigmoid(z) = 1 / (1 + e^-z)     (0 ~ 1 확률)
```

### 오즈 → 로짓 (시그모이드의 역방향)
- **오즈(odds)** = `p / (1-p)` → 성공 확률이 실패 확률의 몇 배인지
- **로짓(logit)** = `log(p / (1-p))` → 0~1 확률을 **-∞ ~ +∞ 실수**로 펼침
- 시그모이드는 로짓의 **역함수** (실수 → 0~1)
- 그래서 로짓 변환하면 `log(p/(1-p)) = β₀ + β₁x` → **선형식이 돼서 해석이 쉬워**

🎯 **계수 해석 (모의고사 단골):** β₁ = 0.5 → x가 1 늘면 **로그 오즈가 0.5 증가** (오즈는 e^0.5 ≈ 1.65배)
- 로짓은 **선형**으로 변하지만 확률 p는 **S자(비선형)** 로 변해

### 학습: LSM 대신 MLE
- **우도(likelihood)**: 이 파라미터가 관측된 데이터를 얼마나 잘 설명하는지
- **MLE(최대우도추정)**: 우도(보통 log-likelihood)를 **최대화**하는 β를 찾음
- ⚠️ **왜 경사하강법을 쓰나?** 로그우도를 미분해서 0으로 두는 방정식의 **닫힌 해(공식 해)가 없어서** 수치 최적화로 풀어야 해

### 이진 → 다중 분류
| | 이진 분류 | 다중 분류 |
|---|---|---|
| 구성 | 선형 + **시그모이드** + **BCE** | 선형 + **소프트맥스** + **CCE** |
| 이름 | 로지스틱 회귀 | 소프트맥스 회귀 |

## 1-4. 모델 평가 🎯(재현율 계산, 정밀도 계산)

### 회귀: MSE (0에 가까울수록), R² (1에 가까울수록)

### 분류: 혼동 행렬
|  | 예측 1 | 예측 0 |
|---|---|---|
| **실제 1** | TP | FN |
| **실제 0** | FP | TN |

| 지표 | 공식 | 의미 |
|---|---|---|
| 정확도 | (TP+TN) / 전체 | 전체 중 맞춘 비율 |
| **정밀도** 🎯 | **TP / (TP+FP)** | "1이라고 예측한 것" 중 진짜 1 |
| **재현율** 🎯 | **TP / (TP+FN)** | "진짜 1" 중 찾아낸 비율 |
| F1 | 2·P·R / (P+R) | 정밀도·재현율의 조화평균 |
| 오분류율 | 1 - 정확도 | 틀린 비율 |

- ⚠️ **오분류율 ≠ F1** (필기의 "F1-score(오분류율)"는 고쳐 둬)
- 🧠 외우는 법: **정밀도는 예측 열(세로) 기준, 재현율은 실제 행(가로) 기준**
- 불균형 데이터(정상 99 : 암 1)에서는 정확도를 믿으면 안 돼 → F1, 재현율 확인
- **ROC-AUC**: 이진 분류에서 0과 1을 얼마나 잘 구분하는지 (1에 가까울수록 좋음)

## 1-5. 과적합·과소적합과 검증 🎯(오버피팅과 분포 변화)

| | 훈련 오류 | 테스트 오류 | 원인 |
|---|---|---|---|
| **과소적합** | 높음 | 높음 | 모델이 너무 단순 (**편향↑**) |
| 적절 | 낮음 | 낮음 | |
| **과적합** | 매우 낮음 | 높음 | 훈련 데이터를 외움 (**분산↑**) → 일반화 실패 |

- **편향-분산 트레이드오프:** 한쪽을 줄이면 다른 쪽이 늘어서 **둘이 동시에 줄지 않아**
- **분포 변화:** 훈련 데이터와 실제 데이터의 분포가 다르면 성능이 달라져 (→ Part 7-6)

### 재표본화 (검증 방법)
1. **Hold-out:** 훈련/검증으로 한 번 나눔. 간단하지만 어떻게 나뉘었냐에 따라 결과가 흔들려
2. **K-fold 교차검증:** K개로 나누고 돌아가며 1개를 검증용으로 K번 → 평균
3. **LOOCV:** K = 데이터 개수 (1개씩 빼서 검증). 정확하지만 매우 느림

- 검증 오류는 **회귀면 MSE**, **분류면 오분류율**로 측정

## 1-6. 경사하강법 🎯(학습률과 수렴, 경사하강법 갱신 방향)

### 핵심 공식
```
w ← w − η · ∂L/∂w        (η = 학습률)
```
- 🎯 **기울기(gradient)는 손실이 가장 가파르게 "증가"하는 방향** → 그래서 **반대 방향(−)** 으로 이동해야 손실이 줄어
- 기울기 = W를 살짝 바꿨을 때 Loss가 변하는 정도. 크면 그 가중치가 오차에 많이 관여한다는 뜻

### 학습률과 수렴 🎯
| 학습률 | 결과 |
|---|---|
| 너무 큼 | **오버슈팅** → 최저점을 지나쳐 진동·발산 |
| 너무 작음 | 수렴이 매우 느리고 지역 최소점에 갇히기 쉬움 |
| 적당 | 안정적으로 수렴 |

- **convex(아래로 볼록)**: 최소점이 하나라 어디서 시작해도 전역 최소점 도달
- **non-convex**: 봉우리·골짜기가 섞여서 **지역 최소점**에 갇힐 수 있어 (신경망은 대부분 이쪽)

### 데이터를 얼마나 보고 한 걸음 가나
| 방식 | 한 번 업데이트에 쓰는 데이터 | 특징 |
|---|---|---|
| 배치 GD | 전체 (1 에포크 = 1 이터레이션) | 안정적이지만 느리고 메모리 큼 |
| 확률적 GD (SGD) | 1개 | 빠르지만 노이즈가 커 |
| **미니배치 GD** | 일부 (예: 64개) | 둘의 절충. 실무 표준 |

- 🎯 **작은 배치의 정규화 효과:** 노이즈 덕분에 뾰족한 최소점(sharp minima)을 피하고 **평평한 최소점(flat minima)** 으로 가서 일반화가 좋아져

## 1-7. 비지도 학습 🎯(K-means와 계층적 군집, 비지도학습 사례, 클러스터링과 표준화)

정답 라벨 **없이** 데이터 구조를 찾는 학습이야

### K-means vs 계층적 군집
| | K-means | 계층적 군집 |
|---|---|---|
| K(군집 수) | **미리 정해야 함** | 미리 안 정해도 됨 |
| 방법 | ① 중심 K개 배치 → ② 가까운 중심에 할당 → ③ 중심 재계산 → 반복 | 가까운 것끼리 하나씩 합쳐 나감 |
| 결과 | K개 그룹 | **덴드로그램(트리)** → 원하는 높이에서 잘라 군집 수 결정 |
| 목표/기준 | **군집 내부 변동(within-cluster variation) 최소화** | linkage: **single(최소 거리)** / **complete(최대 거리)** / **average(평균 거리)** |
| 주의 | 초기 중심에 따라 결과가 달라져 | 데이터가 많으면 느려 |

- 🎯 **클러스터링 전에 표준화하는 이유:** 거리(유클리디안) 기반이라 **단위가 큰 변수가 거리를 독점**하는 걸 막으려고

### 차원 축소: PCA
- 데이터 분산이 가장 큰 방향(주성분)으로 축을 새로 잡아 차원을 줄임

### 🎯 비지도학습 사례 📝
- **고객 세분화**(구매 패턴으로 군집), **이상 탐지**(정상 패턴에서 벗어난 데이터), **차원 축소·시각화**(PCA), **추천**(비슷한 사용자 묶기), **문서·뉴스 자동 분류**(주제별 군집)
- ⚠️ 정답 라벨이 있으면 지도학습이야 (예: 스팸/정상 라벨로 분류 → 지도학습)

### 전처리 / EDA
- 결측치 처리, 범주형 → 숫자 변환
- **표준화**(평균 0, 표준편차 1) vs **정규화**(Min-Max, 0~1)
- 시각화: 히스토그램(분포), box plot(이상치), 산점도(두 변수 관계), 히트맵(상관관계), pairplot(관계 + 분포)

# Part 2. 신경망 기초 (딥러닝의 뼈대)

## 2-1. 퍼셉트론 → XOR 문제 → MLP

```
고전 머신러닝 (사람이 특징을 설계)
   ↓
단층 퍼셉트론 (1958): 입력 × 가중치 + 편향 → 임계값 넘으면 1
   ↓ 한계: 직선 하나라서 XOR을 못 풂
다층 퍼셉트론 MLP: 은닉층 + 비선형 활성화 → 직선 여러 개를 조합
   ↓ 문제: 여러 층의 가중치를 어떻게 학습?
역전파 (1986): 연쇄법칙으로 각 층의 기울기 계산
```

- **MLP 구조:** 입력층 → 은닉층(특징 추출) → 출력층
- ⚠️ **활성화 함수 없이 Linear만 쌓으면** `W₂(W₁x+b₁)+b₂ = (W₂W₁)x + ...` → 결국 직선 하나야. 그래서 **비선형 활성화가 필수** 🎯(비선형 활성화 함수)

### Shallow vs Deep 🎯(Deep Network)
- **Shallow 네트워크:** 은닉층 1개. 히든 유닛마다 ReLU → 꺾인 조각들(piecewise linear)을 합침
- **보편 근사 정리:** 은닉층 **1개라도 유닛이 충분히 많으면** 어떤 연속 함수든 근사할 수 있어
  - ⚠️ "근사할 수 있는 가중치가 **존재한다**"는 뜻이지 "경사하강법으로 **찾을 수 있다**"는 보장은 아니야
- **Deep 네트워크:** 은닉층 여러 개 = 합성함수 → **같은 파라미터로 조각 선형 구역이 훨씬 많아져** 표현력이 좋아
- **깊게 쌓을 때의 문제와 해결 🎯:**
  - 기울기 소실 → **잔차 연결**
  - 학습 불안정 → **정규화(BatchNorm/LayerNorm)**
  - 비선형성 부족 → **FFN·활성화 함수**

## 2-2. 학습 과정

```
① 순전파: 입력 → 층마다 가중치 연산 + 활성화 → 예측 → 정답과 오차 계산
② 손실 계산: MSE(회귀) / 교차 엔트로피(분류)
③ 역전파: 출력 쪽부터 연쇄법칙으로 각 w, b의 기울기 계산
④ 옵티마이저: 기울기로 w, b 업데이트 → 반복
```
- 🎯 **역전파가 효율적인 이유:** 뒤 층에서 계산한 미분 중간값을 앞 층 계산에 **재사용**해서 중복 계산이 없어
- **옵티마이저:** SGD → **Adam** (관성(momentum) + 가중치마다 다른 적응적 학습률)

## 2-3. 활성화 함수의 발전 🎯(비선형 활성화 함수, ReLU)

```
Sigmoid (0~1)
  ↓ 한계: 양 끝에서 기울기 ≈ 0 → 기울기 소실 / 출력이 항상 양수라 학습 비효율
Tanh (-1~1)
  ↓ 0 중심이라 나아졌지만 여전히 양 끝 포화 + exp 연산 비용
ReLU = max(0, x)
  ↓ 양수 구간 기울기 1 → 기울기 소실 완화, 계산 단순
  ↓ 한계: 음수면 출력·기울기 0 → 뉴런이 영구히 죽는 Dying ReLU
Leaky ReLU = max(0.01x, x) / ELU
  → 음수 구간에도 작은 기울기를 남겨 죽은 뉴런 방지
```

## 2-4. 가중치 초기화의 발전

```
0으로 초기화 → 모든 뉴런이 똑같아져서 학습이 안 됨
  ↓
랜덤(가우시안) 초기화 → 깊어지면 W가 계속 곱해져서 기울기 소실/폭발
  ↓
Xavier 초기화: Var(W) = 1/n_in → 입출력 분산을 일정하게 유지
  ↓ 전제: 활성화가 원점 대칭·선형에 가까움 (tanh, sigmoid용)
  ↓ ReLU는 음수를 잘라서(비대칭) 분산이 절반으로 줄어듦
He 초기화: Var(W) = 2/n_in → ReLU용
```
- ⚠️ 필기의 "자비에: tanh 사용해서 연산 어려움"은 틀렸어. 자비에는 **tanh에 맞게 설계**된 거고, 문제는 **ReLU**에서 생겨

## 2-5. 과적합 막기 (규제)
| 방법 | 원리 |
|---|---|
| **L2 (Ridge)** | 큰 가중치에 제곱 패널티 → 모든 가중치가 골고루 작아짐 |
| **L1 (Lasso)** | 절댓값 패널티 → 덜 중요한 가중치가 **완전히 0** (변수 선택 효과) |
| Elastic Net | L1 + L2. 변수가 많고 서로 상관될 때 |
| **드롭아웃** | 학습 중 뉴런을 확률 p로 끔 → 앙상블 효과. **Inverted dropout**: 학습 때 출력을 1/(1-p)배 키워서 테스트 때 추가 연산 없음 |
| **조기 종료** | 검증 오류가 다시 오르기 시작하면 멈춤 |
| **데이터 증강** 🎯 | 회전·뒤집기 등으로 데이터 양과 다양성을 늘려 과적합 방지, 일반화 향상 |

## 2-6. 학습 안정성
- **입력 표준화:** 손실 지형을 원형에 가깝게 만들어 경사하강법의 진동을 줄이고 빨리 수렴하게 함
- **학습률 스케줄:** 계단식(정체될 때마다 낮춤) / 코사인(처음 크게 → 나중에 미세하게) / 선형 감소 / 역제곱 / 일정값
- **하이퍼파라미터 탐색:** 그리드(모든 조합) / 랜덤(무작위 조합, 보통 더 효율적)
- **손실 곡선 진단:**
  - 초반부터 손실이 안 줄어 → 초기화 문제
  - 손실이 크게 안 떨어져 → 학습률 낮추기
  - 훈련↑ 검증↓로 벌어짐 → 과적합
  - 🎯 **훈련·검증 차이는 작은데 성능이 낮아** → 모델 용량 부족 → **더 큰 모델**

# Part 3. 자연어 처리 기본 및 심화

## 3-1. 단어를 숫자로: 원-핫 → 워드 임베딩 🎯(원-핫 인코딩의 한계, CBOW와 Skip-gram)

```
원-핫 인코딩: 단어 하나만 1, 나머지 0
  ↓ 한계 ① 단어 수만큼 차원이 커지고 대부분 0 (희소, 차원의 저주)
  ↓ 한계 ② 모든 단어 쌍의 유사도가 0 → 유의어 관계를 표현 못 함
워드 임베딩: 밀집된 실수 벡터로 표현 → 비슷한 단어는 공간에서 가깝게
  ↓ 대표 방법: Word2Vec (주변 단어로 의미를 학습)
```

| | **CBOW** | **Skip-gram** |
|---|---|---|
| 예측 방향 | **주변 단어 → 중심 단어** | **중심 단어 → 주변 단어** |
| 학습 속도 | 빠름 | 느림 |
| 희귀 단어 | 약함 | **강함** (적은 데이터에도 좋음) |

- **윈도우 크기:** 중심 단어 주변 몇 개를 문맥으로 볼지
- GloVe: 말뭉치 전체의 동시 등장 통계를 사용
- ⚠️ **정적 임베딩의 한계:** 단어 하나에 벡터 하나라서 "밤(night)"과 "밤(chestnut)"을 구분 못 해 → 나중에 BERT의 **문맥 임베딩**이 해결

### 🎯 문장 임베딩과 코사인 유사도
- 문장을 벡터 하나로 표현하고 **코사인 유사도**(두 벡터의 각도)로 비교
- 1 = 같은 방향(의미 비슷), 0 = 무관(직각), -1 = 반대
- 거리 대신 각도를 쓰는 이유: 벡터 길이(문장 길이 등)의 영향 없이 **방향(의미)** 만 비교하려고

### 토큰화 (실습 연결)
- 서브워드 토큰화(BPE, WordPiece)로 **OOV(사전에 없는 단어)** 를 줄임: "자연어처리" → "자연", "##어", "##처리"

## 3-2. 순차 데이터 → RNN 🎯(RNN 순환 구조)

**순차 데이터의 특징:** 순서가 중요하고, 앞뒤가 멀리 떨어져 있어도 연관될 수 있고(장기 의존성), 길이가 제각각이야
→ MLP·CNN은 **고정 길이 입력**만 받아서 처리가 어려워

**RNN:**
- **hidden state**에 이전 정보를 담아서 다음 시점으로 넘김
- `h_t = tanh(W_hh·h_{t-1} + W_xh·x_t + b)` → 모든 시점에서 **같은 가중치 W를 공유**
- 가변 길이 입력이 가능하고, 이전 입력을 기억해
- 구조 유형: one-to-one / one-to-many / many-to-one / many-to-many

### RNN의 한계 🎯(RNN 기울기 소실)
- 역전파할 때 **같은 W가 시퀀스 길이만큼 계속 곱해져** → 기울기 **소실**(0으로) 또는 **폭발**
- 폭발은 **그래디언트 클리핑**(잘라내기)으로 막을 수 있지만, **소실은 해결이 안 돼서** 구조를 바꿔야 해 → LSTM

## 3-3. LSTM (게이트로 소실 완화) 🎯(LSTM 상태 구조, LSTM 게이트)

**상태 2개:**
- **hidden state h**: 단기 정보
- **cell state C**: 장기 정보 (읽기·지우기·쓰기 가능)

**게이트 3개** (sigmoid → 0~1 사이 값: 0이면 닫힘, 1이면 열림)
| 게이트 | 역할 |
|---|---|
| **Forget** | 이전 cell state에서 무엇을 **버릴지** (0 = 다 잊음, 1 = 그대로 유지) |
| **Input** | 새 정보 중 얼마를 cell state에 **쓸지** |
| **Output** | cell state 중 얼마를 hidden state로 **내보낼지** |

- forget gate: `f_t = σ(W_f · [h_{t-1}, x_t] + b_f)` → 이전 hidden과 현재 입력을 **이어 붙여서(concat)** 계산
- 🎯 **왜 기울기 소실이 줄어드나?** cell state가 `C_t = f_t ⊙ C_{t-1} + i_t ⊙ C̃_t`처럼 **덧셈(+)** 으로 업데이트돼서 기울기가 곱셈으로 깎이지 않고 잘 전달돼 (ResNet 잔차 연결과 비슷한 원리)
- **GRU**: LSTM을 단순화한 버전 (여전히 RNN 계열)
- ⚠️ LSTM도 여전히 **순차 구조**라서 긴 문장에서 정보가 희석되는 문제가 완전히 사라지진 않아

## 3-4. 언어 모델 → 기계 번역의 발전

- **언어 모델:** 이전 단어들이 주어졌을 때 **다음 단어의 확률 분포**를 예측. 문장 확률 = 각 단어 조건부 확률의 곱
- **N-gram:** 연속된 n개 단어 묶음 → **직전 n-1개 단어**만 보고 다음 단어 예측
  - ⚠️ 필기의 "직전 3개 단어만 고려"는 4-gram일 때 얘기야

```
SMT (통계적 기계번역): 번역 모델 + 언어 모델 (베이즈 룰)
  ↓ 한계: 구조 복잡, 수작업 많음, 유지·확장 어려움
NMT (신경망 기계번역): Seq2Seq
```

## 3-5. Seq2Seq 🎯(Seq2Seq와 Transformer)

- **번역은 입력·출력 길이가 달라서** 길이가 다른 시퀀스끼리 매핑해야 해
- **인코더 LSTM:** 입력을 한 단어씩 읽어서 **고정 길이 벡터 하나**로 요약
- **디코더 LSTM:** 그 벡터로 출력 문장을 생성
- 인코더·디코더가 하나의 네트워크라서 **End-to-End로 함께 학습**
- **Teacher Forcing:** 학습 초반엔 예측이 엉망이니까 **정답 단어를 디코더 입력으로 넣어줘서** 빠르고 안정적으로 학습
- **출력 방법:**
  - **Greedy:** 매번 확률 최고 단어 선택 → 되돌릴 수 없어
  - **Beam search:** 매 단계 **상위 k개 후보**를 유지 → `<EOS>`까지 간 후보들을 로그확률 합으로 비교

### Seq2Seq의 한계: Bottleneck 문제
- 문장 전체 의미를 **마지막 hidden state 벡터 하나**에 몰아넣으니 정보가 손실돼 → **Attention** 등장

## 3-6. Attention 🎯(어텐션)

**아이디어:** 디코더가 단어를 만들 때마다 **인코더의 모든 hidden state 중 필요한 부분에 직접 집중**

**계산 3단계** (디코더 hidden = Query, 인코더 hidden들 = Values)
1. Query와 각 Value의 **유사도 점수** 계산 (dot-product / multiplicative(W 끼움) / additive(작은 MLP))
2. **softmax** → 확률 분포(attention distribution)
3. 그 확률로 Values를 **가중합** → context vector

**효과 4가지**
- Bottleneck 해결 (모든 인코더 상태에 접근)
- 기울기 소실 완화 (멀리 있는 단어와 직접 연결)
- **해석 가능성**: 어디에 집중했는지 보여서 근거를 확인할 수 있음
- **정렬(Alignment)**: 단어 매핑을 따로 학습할 필요 없이 자동으로 배움
- 번역 평가 지표: **BLEU** (사람 번역과 얼마나 비슷한지)

## 3-7. RNN의 근본 한계 → Self-Attention 🎯(셀프-어텐션)

**RNN(+Attention)에 남은 한계**
1. **장기 의존성:** 멀리 있는 단어끼리 만나려면 시퀀스 길이만큼 단계를 거쳐야 함
2. **병렬화 불가:** 앞 단계가 끝나야 다음 단계 계산 → GPU를 못 살림

**Self-Attention:** Attention을 **한 문장 내부**에 적용 → 모든 단어가 서로 직접 상호작용
- 순차 연산 수가 길이에 따라 늘지 않고, **최대 상호작용 거리 O(1)** → **병렬 처리 가능** 🎯

**Q, K, V 세 가지 벡터**
| 벡터 | 역할 |
|---|---|
| Query | "나는 어떤 정보를 찾고 있나?" |
| Key | "나는 어떤 정보를 가지고 있나?" (Query와 비교되는 용도) |
| Value | 실제로 전달할 내용 (가중합되는 대상) |

**공식 (가장 중요)**
```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```
- 🎯 i번째 단어의 최종 출력 = **모든 단어의 Value를 어텐션 가중치(softmax 확률)로 가중합**
- ⚠️ 필기 고칠 곳: "내적을 디멘션으로 나누고 밸류를 곱한 뒤 softmax"가 아니라 **√d_k로 나누고 → softmax → 그다음 V를 곱해**
- **Scaled:** 차원이 크면 내적값이 커져서 softmax가 너무 뾰족해지고 기울기가 소실되니까 **√d_k로 나눠** 안정화
- ⚠️ 학습되는 파라미터는 **W_Q, W_K, W_V**(+ 출력 W_O)야. 어텐션 점수는 계산 결과지 파라미터가 아니야

### Self-Attention의 한계 3개 → 해결 3개 (세트로 외우기)
| 한계 | 해결 |
|---|---|
| ① 순서 정보가 없음 | **Positional Encoding** (sinusoidal 고정 / learned 학습형) |
| ② 비선형성 부족 (가중평균은 선형 결합) | **Feed-Forward Network** (FC + ReLU) |
| ③ 미래 단어를 미리 봄 | **Masked Self-Attention** (미래 위치 점수를 -∞로) |

## 3-8. Transformer 🎯(멀티-헤드 어텐션)

**RNN 없이 Attention만으로** 만든 인코더-디코더 구조

- **Multi-Head Attention 🎯:** 헤드 하나는 한 관점만 봐서, **여러 헤드로 다양한 관점(문맥, 시제, 품사 등)** 을 동시에 포착
- **Residual Connection:** 입력을 출력에 더해서 변화량만 학습 → 깊어도 학습이 잘 되고 위치 정보도 유지
- **Layer Normalization:** 층마다 값을 정규화해서 안정적이고 빠르게 학습

| | 인코더 | 디코더 |
|---|---|---|
| 문맥 | **양방향** | **단방향** (왼→오) |
| Self-Attention | 마스크 없음 | **Masked** |
| 블록 구성 | Self-Attn → Add&Norm → FFN → Add&Norm | Masked Self-Attn → Add&Norm → **Cross-Attn** → Add&Norm → FFN → Add&Norm |

- **Cross-Attention:** **Query는 디코더**에서, **Key·Value는 인코더**에서 가져옴 → 입력과 출력을 연결
- 트랜스포머는 고정된 패턴이 아니라 레이어마다 **CNN처럼(주변), RNN처럼(순차), MLP처럼(전체 균등)** 필요한 방식을 **스스로 학습**해 🎯(모의고사 함정)
- 병렬 처리가 뛰어나서 **대규모 사전학습**에 딱 맞음 → NLP 표준이 됨

```
🧭 한 줄 흐름 (외우기)
RNN (기울기 소실) → LSTM (게이트로 완화) → Seq2Seq (LSTM 2개)
→ Bottleneck → Attention 추가 → 병렬화 한계 → Transformer (Attention만)
```

| | RNN 계열인가? |
|---|---|
| RNN, LSTM, GRU | ✅ |
| Attention, Transformer | ❌ (재귀 없이 모든 요소를 한 번에 비교) |

## 3-9. 사전학습 언어 모델 🎯(텍스트 파운데이션 모델, 사전학습과 파인튜닝)

**사전학습 → 파인튜닝 패러다임**
- **사전학습:** 대규모 텍스트로 일반적인 언어 패턴·지식 학습
- **파인튜닝:** 그 파라미터로 시작해서 특정 태스크에 맞게 추가 학습
- 워드 임베딩만 사전학습하면 위쪽 네트워크는 랜덤 초기화라 비효율적 → **모델 전체를 사전학습**하는 게 강력함

| 구조 | 대표 | 사전학습 방법 | 잘하는 것 |
|---|---|---|---|
| **Encoder** | **BERT** | **Masked LM** + **NSP**(다음 문장 예측) | 이해 (분류, 개체명 인식, QA) |
| **Encoder-Decoder** | **T5** | **Span Corruption** (연속 토큰을 지우고 복원) | 번역, 요약 |
| **Decoder** | **GPT** | **다음 토큰 예측** (Causal LM) | 생성 |

- **BERT 입력** = Token + **Segment**(어느 문장인지) + Position 임베딩. `[CLS]` = 시작(NSP 분류용), `[SEP]` = 문장 구분
- BERT 한계: 이해는 잘하지만 **생성 태스크엔 부적합** → 생성은 디코더 모델
- ⚠️ 필기 고칠 곳: Decoder 모델의 사전학습은 "NSP"가 아니라 **다음 토큰 예측**이야. NSP는 BERT의 Next Sentence Prediction
- GPT-1으로 분류할 때: `[START]`, `[DELIM]`, `[EXTRACT]` 토큰을 붙이고 `[EXTRACT]` 위치의 hidden state에 분류기를 연결

### GPT-3 → In-context Learning 🎯(Zero-shot CoT, Few-shot CoT)
- **파인튜닝 없이** 프롬프트 속 예시만 보고 새 태스크를 수행. 모델이 클수록 강하게 나타나
- 성능: **zero-shot < one-shot < few-shot**
- **CoT (Chain-of-Thought):** 중간 추론 단계를 거쳐서 답하도록 유도
  - **Zero-shot CoT:** 예시 없이 **"단계별로 생각해 보자(Let's think step by step)"** 한 줄 추가
  - **Few-shot CoT:** **풀이 과정까지 담긴 예시**를 몇 개 보여줌 (더 강력, 프롬프트 길어짐)

# Part 4. 딥러닝 & 영상 모델

## 4-1. FC(완전연결) 네트워크의 한계 → CNN 🎯(CNN 공간 구조)

- FC(FCN)는 이미지를 **1차원으로 펴서** 넣음 → 주변 픽셀 관계(공간 구조)를 버리고, 파라미터도 폭증
  - 예: `W(10×3072) · x(3072×1) = (10×1)` → 행렬곱은 **A의 열 수 = B의 행 수**여야 해
- **CNN:** 2D 격자 구조를 유지하면서 **필터(커널)를 슬라이딩**해 특징 맵을 뽑음
  - 필터 1개 → 특징(활성화) 맵 1개. 필터 6개면 맵 6개
  - 필터 깊이 = 입력 채널 수
  - 필요한 곳: 지엽적 정보, 실시간, 저전력

### CNN 핵심 부품
| 부품 | 역할 | 학습 파라미터 |
|---|---|---|
| **합성곱(Conv)** | 필터로 특징 추출 | W, b 있음 |
| **ReLU** | 비선형성 → Conv를 쌓는 게 의미 있어짐 | 없음 |
| **Max Pooling** 🎯 | 영역의 최댓값만 남겨 해상도↓, 연산량↓, **작은 위치 변화에 강건** | **없음** (나머지 정보를 버려서 손실 큼) |
| **Stride Conv** | 필터를 S칸씩 이동 → 해상도를 줄이면서 **가중치도 학습** | 있음 (풀링보다 정보 손실 적음) |
| **Padding** | 가장자리를 0으로 채워 해상도 유지 | 없음 |

### 🎯 CNN Inductive Bias (귀납적 편향)
- **지역성(Locality):** 가까운 픽셀끼리 관련 있다
- **이동 동변성/불변성(Translation Equivariance/Invariance):** 물체 위치가 바뀌어도 같은 특징을 잡아냄 (Conv는 위치가 따라 이동하는 동변성, Pooling이 불변성을 더해 줌)
- **가중치 공유(Weight Sharing):** 같은 필터를 이미지 전체에 재사용 → 파라미터 효율 ↑
- 덕분에 **적은 데이터로도 잘 작동**해

### 🎯 수용 영역(Receptive Field)
- 한 출력이 입력에서 **볼 수 있는 영역의 크기**. 층이 깊어질수록 넓어짐
- 넓히는 방법: **깊게 쌓기**, **pooling**, **stride**, **dilated conv**
- 3×3 conv 2개 = 5×5 수용 영역, 3개 = 7×7

## 4-2. CNN 모델의 변천사 🎯(CNN·FC 파라미터 계산, Feature Map 메모리, 1×1 Convolution)

```
AlexNet → VGG → GoogLeNet → ResNet → MobileNet
```

### ① AlexNet
- Conv 5개 + ReLU + Max pooling + FC 3개 = **8층**. 출력은 softmax로 1000개 클래스

### ② VGG-16 (AlexNet의 큰 커널 → 작은 커널을 깊게)
- **5×5 1개 대신 3×3 2개:** 수용 영역은 같은데 **파라미터·연산량↓, 깊이↑(비선형↑)**
  - 파라미터: 5×5는 25C², 3×3 두 개는 18C²
- 해상도를 줄일 때마다 **채널을 늘려서** 층마다 연산량을 비슷하게 유지

### ③ GoogLeNet: 1×1 Conv로 차원 축소 (Inception 모듈)

### 🎯 1×1 Convolution
- 공간적으로 **픽셀 1개만** 봄 → 주변 패턴은 못 잡고 **채널 방향 선형 결합만** 수행
- 용도: **채널 수를 줄여서 연산량 감소** (차원 축소), 채널 간 정보 섞기
- 연산량 = `H' × W' × Cin × Cout` (K=1이니까)

### ④ ResNet (깊어지면 오히려 성능↓ → 잔차 연결)
- 🎯 **열화(Degradation) 문제:** 층을 더 쌓았더니 **훈련 오류조차 높아짐**
  - ⚠️ 과적합이 아니야! 과적합이면 훈련 오류는 낮아야 해
  - 깊은 모델이 **항등 함수(입력 그대로 내보내기)조차 못 배우는** 과소적합 현상
- **해결: 잔차 블록** `output = F(x) + x`
  - 학습이 안 되면 F(x) = 0으로 두고 x를 그대로 넘기면 됨 → **최소한 얕은 모델 성능은 보장**
  - 덧셈 경로로 기울기가 잘 전달됨 + **He 초기화**와 **배치 정규화**
- **보틀넥 잔차 블록:** `1×1(채널 축소) → 3×3 → 1×1(채널 복원)` → 연산 효율 ↑ → **100층 이상** 가능
- 🎯 **GAP (Global Average Pooling):** 끝단의 여러 FC 대신 채널별 평균값 1개씩 추출 → **파라미터 0개**라 과적합↓, **입력 해상도가 달라도** 고정 길이 벡터를 얻음. 마지막 FC 1개만 남김
- ⚠️ 필기 고칠 곳: **stem은 입력부**(해상도 줄이고 저수준 특징 추출)이고, GAP로 FC를 줄이는 건 **출력부(head)** 얘기야

| | LSTM | ResNet |
|---|---|---|
| 분야 | 순차 데이터 | 이미지 |
| 문제 | 문장이 길면 앞 정보 희석 | 층이 깊으면 학습 어려움 |
| 해결 | 게이트 + 덧셈 cell state | 지름길(skip)로 원본 전달 |
| 관계 | 직접 계승 관계는 없지만 **"덧셈 경로로 기울기 보존"** 이라는 아이디어가 비슷 |

### ⑤ MobileNet (모바일용 경량화)
- 일반 Conv는 **공간과 채널을 한 번에** 처리해서 연산량이 큼: `9C²HW` (3×3, 입출력 채널 C)
- **Depthwise Separable Conv:**
  - **Depthwise:** 채널마다 따로 3×3 → `9CHW`
  - **Pointwise:** 1×1로 채널 결합 → `C²HW`
- 🎯 **공간 연산과 채널 연산을 분리**해서 약 **1/9**로 감소

### CNN의 한계
- 긴 거리 의존성(멀리 떨어진 영역의 관계)을 잡기 어려움
- 순서 정보 반영이 어려움
- pooling·stride로 위치 정보가 손실돼서 픽셀 단위 복원이 어려움

## 4-3. 이미지에 Attention → ViT 🎯(CNN과 ViT, ViT Positional Embedding)

- **Self-Attention (이미지):** 같은 이미지 안 패치끼리 유사도 → 비슷한 패치끼리 묶이는 클러스터링 효과
- **Cross-Attention:** 서로 다른 데이터(이미지 ↔ 텍스트) 사이에서 Q와 K·V를 각각 가져옴

### ViT 동작 순서
1. 이미지를 **패치**로 자름
2. 각 패치를 **1D로 flatten** → 임베딩 (패치 = 토큰)
3. **Position Embedding** 추가 (주로 학습형)
4. **Transformer 인코더** L개 통과: `정규화 → Multi-Head Attention → 정규화 → MLP`
5. **MLP Head**로 분류 (Head만 바꿔 다른 태스크에 쓰면 **Linear probing**)

### 🎯 Positional Embedding 종류
| 종류 | 특징 |
|---|---|
| **학습형 (Learnable)** | 위치마다 벡터를 만들고 함께 학습. 데이터에 맞춰지지만 **해상도가 바뀌면 다시 학습** 필요 |
| **사인파 (Sinusoidal)** | sin/cos 주파수 조합으로 고정. 저주파 = 대략적 위치, 고주파 = 정밀 위치. 학습 X |
| **상대 위치** | "두 패치가 몇 칸 떨어져 있나"를 인코딩 → 해상도 변화에 유리, 절대 위치는 약함 |

- 위치 임베딩이 없으면 Attention은 **패치 순서를 섞어도 결과가 같아** (순서 정보 0)

### CNN vs ViT 🎯
| | CNN | ViT |
|---|---|---|
| 보는 방식 | **지역(Local)** → 깊어지며 넓어짐 | **전역(Global)**: 첫 층부터 모든 패치 관계 |
| Inductive Bias | **강함** (지역성, 이동 불변) | **약함** (위치 관계도 스스로 학습) |
| 데이터 | **적어도 잘 됨** | **대규모 데이터** 필요. 작으면 ResNet이 나음 |
| 강점 | 실시간·저전력 | 긴 거리 의존성, 멀티모달의 기준 구조 |

### ViT 보완 모델
- **DeiT (증류 학습):** 학생 ViT가 **증류 토큰**을 추가로 받아 **선생님 CNN의 출력(logit)** 을 따라 하도록 학습 → CNN의 inductive bias를 지식으로 전달받음
- **Swin Transformer:** 전체 패치끼리 어텐션하면 연산량이 커서 → **국소 윈도우 안에서만 어텐션**, 다음 층에서 **윈도우를 이동(shifted window)** → 반복하면서 전역 효과
- **비전 백본:** 특징 추출 뼈대 (CNN: ResNet, VGG, ConvNeXt / Transformer: ViT, Swin)

# Part 5. 파운데이션 모델 · LLM · 멀티모달

## 5-1. 파운데이션 모델 🎯(텍스트 파운데이션 모델, 파운데이션 모델 서비스 개발, AI 스케일링)

**정의:** 대규모 데이터로 사전학습해서 **여러 작업에 범용으로 적응**할 수 있는 기반 모델

- **구성 요소:** ① 자가(자기지도)학습 알고리즘 ② 빅데이터 ③ Attention 기반 트랜스포머
- **특징:** 대규모 사전학습 / 높은 미세조정 성능(적응성) / 다양한 작업(범용성)
- **스케일링 법칙:** 모델 크기·데이터·연산량을 늘리면 성능이 **예측 가능하게** 좋아짐 (추세선으로 예측)
- **창발성:** 규모가 커지면 작은 모델엔 없던 능력(예: In-context learning)이 갑자기 나타남
- **활용:** 대규모 데이터 → 사전학습 → zero-shot / few-shot / fine-tuning

### 🎯 개방형 vs 폐쇄형 LLM
| | 개방형 (오픈소스) | 폐쇄형 |
|---|---|---|
| 가중치 | **공개** | 비공개 |
| 사용 | 로컬·온프레미스에 직접 배포 | **API**로 사용 |
| 장점 | 데이터가 밖으로 안 나가서 보안 유리, 커스터마이징 | 관리 부담 적고 성능 강함 |

### 📝 파운데이션 모델 서비스 개발 흐름
- 모델 선택(API vs 오픈소스) → **프롬프트** → 부족하면 **RAG** → 그래도 부족하면 **파인튜닝** → 평가 → 경량화·배포
- 고려할 것: 비용, 지연시간, 보안(데이터 유출), 환각

### 📝 Physical AI
- 디지털 세계를 넘어 **센서로 물리 세계를 인지하고 로봇 등으로 실제 행동**하는 AI (자율주행, 로봇)
- 스케일링 법칙이 언어에서 성공한 것처럼 물리 세계 데이터로 확장하려는 흐름

## 5-2. LLM 정렬: 사전학습 → 지시학습 → 선호학습 🎯(지시 학습 데이터, RLHF, LLM 안전 정렬)

```
사전학습 GPT-3: 다음 토큰 예측만 잘함
  ↓ 한계: 지시를 잘 안 따르고, 유해한 답변 가능, jailbreak 가능
지시학습 (Instruction Tuning, SFT)
  ↓ 한계: 정답이 없는 개방형 태스크(어느 답이 더 좋은가)는 학습 어려움
선호학습 (RLHF)
  ↓ 한계: 보상 모델 + 강화학습 루프가 복잡하고 불안정
DPO
```

### ① 지시학습 🎯
- "요약해줘", "번역해줘" 같은 **(지시문, 수행 결과)** 쌍으로 파인튜닝
- 대표: **FLAN** → **태스크 단위로 훈련/테스트를 나눠서** 평가 → 처음 보는 태스크도 잘하게 됨 (zero-shot 일반화)
- 🎯 **일반 파인튜닝 vs Instruction-tuning:** 파인튜닝은 보통 **한 가지 태스크**에 맞춤 / 지시학습은 **여러 태스크를 지시문 형식으로** 학습해서 새 지시에도 대응

### ② RLHF 🎯(학습 절차, 학습 파이프라인)
```
0. 사전학습
1. SFT (지시학습)
2. 보상 모델(Reward Model) 학습: 사람이 답변들의 선호 순위를 매긴 데이터로
3. 강화학습(PPO)으로 정책(LLM) 최적화: 보상이 높아지도록
```
- 효과: 해로운 응답(RealToxicity)·거짓말(TruthfulQA, 환각) 감소

### ③ DPO 🎯(선호 학습)
- **보상 모델도, 강화학습 루프도 없이** "A가 B보다 낫다" 선호 쌍을 **손실함수에 직접** 넣어 정렬 → 지도학습처럼 간단

### 🎯 안전 정렬 목적
- 유해·편향·위험한 답변을 피하고 **인간의 의도와 가치에 맞게** 조정

## 5-3. 디코딩 알고리즘 🎯(Top-k, Top-p 샘플링)

LLM은 다음 토큰의 **확률 분포**를 출력함 → 어떻게 고를지가 디코딩이야 (자동회귀 생성)

```
Greedy: 항상 최고 확률 → 단조롭고 반복적
  ↓
Beam search: 상위 k개 경로 유지 → 더 좋은 문장, 그래도 단조로움
  ↓
Sampling: 확률대로 무작위 추출 → 다양하지만 이상한 토큰도 나옴
  ↓
Temperature: 분포를 뾰족(낮음 → 보수적) / 평평(높음 → 창의적)하게 조절
  ↓
Top-k: 상위 k개 토큰 안에서만 샘플링 → k가 고정이라 상황에 안 맞을 수 있음
  ↓
Top-p (Nucleus): 누적 확률이 p에 도달할 때까지의 토큰 집합에서 샘플링 → 후보 수 자동 조절
```

## 5-4. 프롬프트 엔지니어링 🎯(프롬프트 디자인)

- **입력 프롬프트 = 지시 + 예시**, **지시 = 시스템 프롬프트 + 유저 쿼리**
- zero-shot / few-shot / CoT (3-9 참고)

| | 프롬프트 디자인 | 프롬프트 튜닝 |
|---|---|---|
| 방법 | 사람이 직접 문장을 설계 | **학습 가능한 가상 토큰**을 입력에 추가해 **그 임베딩만 학습** |
| 모델 | 고정 | 고정 (지식 손실 없음) |
| 장점 | 추가 학습 없음 | 적은 비용으로 새 데이터셋 대응 |
| 한계 | 성능 향상 제한적 | 학습 필요 |

## 5-5. LLM 평가 🎯(LLM-as-Judge 평가 편향)

- **정답 있음:** 정확도 (예: MMLU 객관식)
- **정답 없음:**
  - 사람 답과의 overlap (문장 벡터 → 코사인 유사도)
  - **Perplexity** (낮을수록 자연스러움)
  - 사람 선호도 평가
  - **LLM-as-Judge (G-Eval)**: 다른 LLM이 채점

🎯 **LLM-as-Judge 편향**
| 편향 | 내용 | 대응 |
|---|---|---|
| **자기 편향** | 자기(같은 계열) 모델 답에 후한 점수 | 다른 모델로 채점 |
| **위치 편향** | 먼저(또는 나중에) 제시된 답을 선호 | 순서를 바꿔 두 번 평가 |
| **장황함 편향** | 길고 자세한 답을 더 좋게 봄 | 길이와 무관한 기준 명시 |

- 그래서 LLM 채점은 **1차 필터**고, 최종 판단은 사람이 해

## 5-6. 합성 데이터와 지식 증류 🎯(Knowledge Distillation, Teacher–Student)

- **합성 데이터:** 사람이 만든 소량 데이터를 기반으로 LLM이 대규모로 확장 → 너무 비슷하거나 너무 다른 건 삭제
  - 주의: 라벨 품질 불일치, **환각** → 프롬프트 정교화, 검증, 실데이터 혼합
- **지식 증류 (Teacher → Student):**
  - 큰 **선생님 모델**의 지식을 작은 **학생 모델**에 압축 전달
  - 학생은 선생님의 **soft label**(확률 분포 전체)을 따라 하도록 학습 → 정답 하나(hard label)보다 "어떤 오답이 얼마나 비슷한지"까지 배움
  - 결과: 작고 빠른 모델이 큰 모델 성능에 근접 (→ 경량화 기법)

## 5-7. 멀티모달: CLIP → SigLIP → VLM 🎯(CLIP zero-shot, VLM 학습 절차, 문서 이해 VLM, Small VLM)

### CLIP (Contrastive Language-Image Pre-training)
- **텍스트 인코더**(트랜스포머 인코더, 서브워드 토큰) + **이미지 인코더**(ViT 또는 ResNet50, 패치 단위)
- **대조 학습:** 짝이 맞는 이미지-텍스트 쌍의 코사인 유사도는 **높이고**, 안 맞는 쌍은 **낮춤**
- **학습 과정:**
  1. 배치에 N개 쌍
  2. **N×N 유사도 행렬** (대각선이 정답)
  3. 행마다 softmax → 교차 엔트로피 (이미지→텍스트, `dim=1`)
  4. 열마다도 똑같이 (텍스트→이미지, `dim=0`)
  5. 두 loss를 평균
- 🎯 **Zero-shot 분류:** 클래스 이름들을 텍스트 임베딩으로 바꾸고 → 이미지 임베딩과 **코사인 유사도가 가장 높은 클래스** 선택 (추가 학습 없음)
- **CLIP 응용 (Text-to-3D 등):** CLIP은 **고정(freeze)** 해 두고, 텍스트-이미지 유사도를 **손실함수로 써서 생성 대상의 파라미터만** 역전파로 업데이트 (CLIP = 채점관 역할)

### SigLIP (CLIP의 한계 보완)
- CLIP 한계: softmax라서 **이미 충분히 먼 음성 쌍도 계속 밀어내느라** 학습이 낭비됨
- SigLIP: softmax 대신 **sigmoid** → 각 (이미지, 텍스트) 쌍을 **독립적인 이진 분류**로 처리
- ⚠️ 필기의 "SigCLIP"은 **SigLIP**이 맞아

### VLM (Vision-Language Model)
- **멀티모달 정합:** 서로 다른 모달리티를 **공통 임베딩 공간**에 놓아 비교 가능하게 함
- 대표: **LLaVA** (비전 인코더 + LLM)
- 🎯 **학습 절차:** ① 이미지·텍스트 **정렬(Alignment) 사전학습** → ② **VLM 지시학습(Instruction tuning)**
- **Set-of-Mark(SoM):** 객체 탐지·세그멘테이션 모델로 표시를 붙여 VLM의 시각 능력 보완
- 📝 **문서 이해 VLM:** OCR 없이 문서 이미지(표, 차트, 레이아웃)를 직접 이해. 작은 글자 때문에 **고해상도 입력**이 필요해서 토큰과 연산이 늘어나는 게 난제
- 🎯 **Small VLM:** **소형 LLM + 작아진 비전 인코더 + QLoRA/양자화** 조합 → 온디바이스 🎯 (제한된 VRAM에서 양자화 + sLM)
- 한국어 sVLM의 문제: 토크나이저가 영어 중심이라 **한국어는 토큰이 더 잘게 쪼개져** 토큰 수가 늘어남

## 5-8. 생성 모델: Diffusion 🎯(Diffusion 이미지 생성, 멀티모달 비디오 생성)

- **생성 모델:** 데이터셋으로 미지의 데이터 분포를 근사 → 거기서 새 데이터를 샘플링
- **Diffusion:**
  - **Forward:** 이미지에 노이즈를 조금씩 더해 결국 **가우시안 노이즈**로 만듦
  - **Reverse(학습 대상):** 노이즈를 **예측해서 단계적으로 제거**하는 법을 학습
  - 생성: 랜덤 노이즈에서 시작 → 점진적 디노이징 → 이미지
- **LDM (Latent Diffusion):** 이미지를 **저차원 latent**로 압축한 뒤 거기서 diffusion → 연산 효율↑, 품질↑ (Stable Diffusion)
  - ① 텍스트 임베딩 생성 → ② 그 조건으로 latent를 점차 개선해서 이미지 생성
- 🎯 **비디오 생성의 난제:** **프레임 간 시간적 일관성(Temporal Consistency)** 유지

# Part 6. LangChain · Agent

## 6-1. LLM의 한계 → RAG 🎯(RAG)

**LLM의 3가지 한계:** 환각 / 최신 정보 없음 / 도메인(사내) 지식 없음
- 환각 이유: LLM은 검색이 아니라 **그럴듯한 다음 토큰 예측**만 해서 모르는 것도 유창하게 말함

**RAG (검색 증강 생성):** 답하기 전에 관련 문서를 **검색해서 프롬프트에 넣어줌** = 오픈북 시험

```
[준비] 문서 → Loader → Splitter(청킹) → Embedding → Vector Store
[실행] 질문 → Retriever(검색) → 검색된 문서 + 질문 → LLM → 답변
```

| Retriever | 기준 | 예 |
|---|---|---|
| **Sparse** 🎯 | **키워드 일치**(어휘적 유사도) | TF-IDF, BM25 |
| **Dense** 🎯 | **임베딩 벡터의 의미적 유사도** → 동의어도 찾음 | 벡터 검색 |

- **청킹:** `chunk_size`(조각 크기), `chunk_overlap`(경계에서 문장이 잘리지 않게 겹침)
- **장점:** 추가 학습 없이 최신 정보(문서만 교체), 개인화, 출처 제시, 환각 감소
- **한계:** 검색이 틀리면 답도 틀림 (Garbage in, garbage out), 여러 문서 종합 추론에 약함, 프롬프트가 길어져 비용↑
- **LangChain** = 부품 상자 (Loader, Splitter, VectorStore 등) / **LangGraph** = State·Node·Edge로 흐름 조립 (분기·반복 가능)

## 6-2. AI → AI Agent 🎯(AI와 AI Agent, LLM Agent의 특성, AI Agent 동작)

| | AI (모델) | AI Agent |
|---|---|---|
| 동작 | 입력 → 출력 한 번 | **목표를 위해 스스로 판단 → 행동 → 결과 관찰 → 반복** |
| 외부 세계 | 텍스트만 생성 | **도구로 실제 행동** (API 호출, DB 조회 등) |

**Agent 4요소:** **LLM**(두뇌, 판단) + **Tool**(손, 행동) + **Memory**(기억) + **Planning**(계획, 작업 분해)

**LLM Agent의 특성:** 자율성, 도구 사용, 다단계 추론·계획, 기억 → 대신 **비용↑, 느림, 예측 어려움, 디버깅 어려움**
- 흐름을 미리 그릴 수 있으면 Agent 대신 RAG나 일반 코드가 나아

### 🎯 Tool Learning / Tool 활용
- LLM이 **어떤 도구를 쓸지 판단하고 함수 이름과 인자(arguments)를 생성** → 외부 프로그램이 실제 실행 → 결과를 다시 LLM에 전달 → 최종 답변
- ⚠️ LLM이 직접 실행하는 게 아니야. **호출 정보를 생성**하는 거야
- 도구 설명(docstring)을 보고 판단하니까 **설명을 명확히** 써야 해
- 도구 1번 사용 = LLM 최소 2번 호출 (도구 선택 + 결과로 답변)

### ReAct (Reasoning + Acting)
- **Thought → Action → Observation** 반복
- **ReAct = CoT + Tool-use** (생각만 하던 CoT에 실제 행동과 관찰을 추가)

### Memory
- 단기: 현재 대화 기록 / 장기: 세션을 넘어 저장 (RAG 방식으로 검색)

### 🎯 다중 에이전트 시스템
- 역할을 나눠서 협업하고, **공유 State**로 정보를 주고받음
| 패턴 | 구조 |
|---|---|
| Planner-Worker | 계획 → 실행 분리 |
| Supervisor-Worker | 관리자가 전문 에이전트들에게 분배 |
| Reflection | 실행 → 검토 → 개선 반복 (탈출 조건 필수) |
| Debate | 서로 토론해서 결론 |
| Pipeline | A → B → C 순차 가공 |

### 신뢰성
- 입력 가드레일 → **도구 내부 검증(가장 중요, 우회 불가)** → 출력 가드레일
- **HITL**: 환불·삭제 같은 고위험 행동은 사람 승인

## 6-3. 🎯 도메인 특화 AI = 조합
- **PEFT(LoRA) 파인튜닝**(도메인 말투·형식) + **RAG**(도메인 지식 DB) + **Agent**(전문 도구 연결)

# Part 7. 리소스 최적화

## 7-1. 파인튜닝 → 파라미터 효율적 튜닝(PEFT) 🎯(단일 태스크 파인튜닝, 사전학습과 파인튜닝)

**파인튜닝이 필요한 이유:** 파운데이션 모델은 범용이지만 최신 정보나 특정 도메인에 최적화돼 있지 않음
- 프롬프트보다 **훨씬 많은 예제**로 학습 가능, 프롬프트가 짧아져 **토큰·지연시간 절약**
- 이미 좋은 출발점이니까 **작은 학습률**로 보수적으로 시작
- 🎯 **단일 태스크 파인튜닝의 문제: 재앙적 망각(Catastrophic Forgetting)** → 기존 일반 지식을 잊어버림

```
Full Fine-tuning: 모든 파라미터 학습
  ↓ 한계: 메모리 폭발 (가중치 + 기울기 + 옵티마이저 상태)
프롬프트 튜닝: 가상 토큰 임베딩만 학습
Adapter: 레이어마다 작은 모듈 삽입해서 그것만 학습
  ↓
LoRA: 저랭크 행렬로 변화량을 표현 → adapter보다 추가 가중치가 훨씬 적음
```

### LoRA
- `h = Wx + (α/r)·BAx` → **W는 고정**, **B(d×r)와 A(r×d)만 학습**
- 학습 파라미터: d² → **2dr** (예: d=4096, r=8이면 0.39%)
- B를 **0으로 초기화** → 시작 시점엔 원본 모델과 똑같음 → 망각 완화

## 7-2. 경량화가 필요한 이유 → 양자화 🎯(Quantization의 특징, 저비트 Quantization)

**양자화:** 가중치를 표현하는 **비트 수를 줄여서** (FP32 → FP16 → INT8 → INT4) 메모리와 연산을 줄임

| 정밀도 | 파라미터당 | FP32 대비 |
|---|---|---|
| FP32 | 4바이트 | - |
| FP16 | 2바이트 | 1/2 |
| INT8 | 1바이트 | 1/4 |
| INT4 | 0.5바이트 | 1/8 |

- **FP(부동소수점):** 넓은 범위를 유연하게 표현 / **INT(정수):** 계산이 단순하고 빠름
- **수식:** `Q(x) = round(x / scale) + zero_point`, 복원 `x' = (Q - zero_point) × scale`
- 오차의 원인 = **반올림**. 비트가 적을수록 단계가 줄어 오차↑
- **PTQ:** 학습 끝난 뒤 압축 (간단) / **QAT:** 양자화를 고려하며 학습 (손실 적음, 번거로움)
- 🎯 **NF4:** LLM 가중치는 0 근처에 몰린 **정규분포** → 0 근처에 단계를 촘촘히 → **같은 4비트로 일반 INT4보다 오차↓**
- ⚠️ 양자화는 **가중치만** 압축 (활성화·KV 캐시는 그대로) → 피크 메모리 절감은 더 작음
- ⚠️ 연산 직전에 역양자화가 필요해서 **항상 빨라지진 않아**

### QLoRA = 양자화 + LoRA
- 베이스 모델은 **NF4 4비트로 얼리고**, LoRA 가중치만 **BF16 등 높은 정밀도**로 학습
- 메모리를 대폭 줄이면서 목표 태스크 성능은 유지

## 7-3. 모델 경량화 Trade-off 🎯

```
크기 ↓  속도 ↑  전력 ↓      ⟷      정확도 ↓ (특히 낮은 비트, 작은 모델)
```
| 기법 | 줄이는 것 | 대가 |
|---|---|---|
| 양자화 | 비트 수 | 정밀도 손실, 분포 변화에 약해짐 |
| 지식 증류 | 모델 크기 (작은 학생) | 학습 비용, 성능 약간↓ |
| 📝 가지치기 (Pruning) | 덜 중요한 가중치·연결 제거 | 정확도↓ 위험 |
| 경량 구조 (MobileNet) | 연산량 | 표현력 |
| PEFT (LoRA) | 학습 파라미터 | Full FT 대비 성능 약간↓ |

## 7-4. 배포 환경별 경량화 전략 🎯

| 환경 | 특징 | 전략 |
|---|---|---|
| 서버 (GPU) | 자원 넉넉, 정확도 우선 | FP16/BF16, 큰 모델, 필요하면 INT8 |
| 엣지·모바일·온디바이스 | 메모리·전력 제한, 실시간 | **INT8/INT4 양자화**, 증류된 소형 모델, MobileNet 같은 경량 구조, **정수 연산** |

## 7-5. 분포 변화와 OOD 🎯(Distribution Shift, OOD와 Adaptive Sensing)

- **Distribution Shift (분포 변화):** 학습 데이터와 실제 입력의 분포가 달라짐 (예: 맑은 날 사진으로 학습 → 비 오는 날 사용)
- **OOD (Out-of-Distribution):** 학습 분포 **밖의** 입력 → 성능이 크게 떨어지고 자신 있게 틀릴 수 있음

# Part 8. 🧮 계산 문제 모음 (손으로 꼭 풀어보기)

### ① 정밀도·재현율 🎯
TP=40, FP=10, FN=20, TN=30
- 정밀도 = 40/(40+10) = **0.8**
- 재현율 = 40/(40+20) = **0.667**
- F1 = 2·0.8·0.667/(0.8+0.667) ≈ **0.727**
- 정확도 = (40+30)/100 = **0.7** → 오분류율 0.3

### ② R²
RSS = 20, TSS = 100 → R² = 1 - 20/100 = **0.8**

### ③ 로지스틱 계수
β₁ = 0.5 → 로그 오즈 **+0.5**, 오즈 **× e^0.5 ≈ 1.65배**

### ④ CNN 출력 크기 🎯 `(W - K + 2P)/S + 1`
- 32×32, K=5, P=0, S=1 → (32-5)/1+1 = **28**
- 32×32, K=5, P=2, S=1 → (32-5+4)/1+1 = **32** (크기 유지)
- 32×32, K=4, P=0, S=2 → (32-4)/2+1 = **15**

### ⑤ CNN 파라미터 수 🎯 `Cout × Cin × K × K + Cout`
- 입력 3채널, 5×5 필터 6개 → 6×3×5×5 + 6 = **456**
- 입력 64채널, 3×3 필터 128개 → 128×64×9 + 128 = **73,856**

### ⑥ FC 파라미터 수 🎯 `입력 × 출력 + 출력`
- 400 → 120: 400×120 + 120 = **48,120**

### ⑦ Feature Map 메모리 🎯 `C × H' × W' × 4바이트` (FP32)
- 출력 6×28×28 → 4,704개 × 4 = **18,816바이트**

### ⑧ FLOPs(연산량) `H' × W' × Cin × K × K × Cout`
- 28×28 출력, Cin=3, K=5, Cout=6 → 784 × 3 × 25 × 6 = **352,800**

### ⑨ 1×1 Conv 🎯
56×56, Cin=256 → Cout=64
- 파라미터: 64×256×1×1 + 64 = **16,448**
- 연산량: 56×56×256×64 = **51,380,224**
- 같은 조건 3×3이면 연산량 **9배** → 1×1로 채널을 먼저 줄이면 이득

### ⑩ VGG: 5×5 1개 vs 3×3 2개 (채널 C 유지, bias 제외)
- 5×5: **25C²** / 3×3 두 개: **18C²** → 수용 영역은 똑같이 5×5

### ⑪ MobileNet
- 일반: 9C²HW / 분리: 9CHW + C²HW → 비율 = (9 + C)/(9C) ≈ **1/9** (C가 클 때)

### ⑫ LoRA
- d=4096, r=8 → 2×4096×8 = **65,536** (원래 4096² = 16,777,216의 **0.39%**)

### ⑬ 양자화 메모리
- 7B 모델: FP32 **28GB** / FP16 **14GB** / INT8 **7GB** / INT4 **3.5GB**
