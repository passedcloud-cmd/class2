docker에 환경이 이미 설정되어 있음. torch 등이 이미 설치되어 있음.

## 전체 흐름
이 노트북은 "이미지 + 질문(4지선다) → 정답 맞히기" 모델을 만드는 코드
준비(환경/데이터) → 모델 불러오기 → 데이터 포장 → 학습(fine-tuning) → 추론(inference) → 결과 csv 저장


### 소제목별 설명
#### 환경 준비 / 데이터 준비 / 라이브러리, 데이터, 설정
필요한 도구(torch, transformers 등)를 설치
train.csv, test.csv 같은 데이터 파일을 불러오는 준비 단계
`train_df.sample(n=200, ...)` → 전체 학습 데이터 중 200개만 무작위로 뽑아서 쓰겠다

ipykernel 설치 / train.csv, train 폴더와 test.csv, test 폴더와 sample_submission.csv 준비 / 사전 학습 모델 정의, 데이터셋 로드, 학습 데이터 추출 개수 정하기 


#### 모델, Processor
기본 사전학습된 모델을 받아오는 것
모델을 양자화해서 용량을 줄이고 LoRA 적용할 준비
- `AutoModelForVision2Seq.from_pretrained(MODEL_ID, ...)` → Qwen2.5-VL-3B라는, 이미 만들어져서 공개된 "이미지+텍스트를 이해하는 AI 모델"을 다운로드해서 가져오기
- `BitsAndBytesConfig(load_in_4bit=True, ...)` → 가져온 모델을 4비트로 양자화(용량 압축, 원래 정밀도를 줄여서 메모리를 덜 쓰게 만드는 것)해서 가져오기
- `LoraConfig(...)` + `get_peft_model(...)` → LoRA 준비. 모델 전체(수십억 개 파라미터)를 다 학습시키면 시간/메모리가 많이 필요하므로 일부 작은 부분만 추가로 학습

양자화, 프로세서 정의, 사전학습 모델 가져오기, LoRA 세팅 , PEFT 모델 생성


#### 프롬프트 템플릿
모델 지시사항, 프롬프트 설정
SYSTEM_INSTRUCT로 모델에게 어떻게 답해야 하는지 규칙을 정해주는 부분
build_mc_prompt() 함수가 실제 문제(질문+보기 4개)를 규칙에 맞춰 텍스트로 조립


#### Custom Dataset, Collator
데이터셋을 준비
`VQAMCDataset` → csv의 각 행(이미지 경로, 질문, 보기, 정답)을 모델이 이해할 수 있는 형태(이미지+대화 메시지)로 하나씩 바꿔주는 역할
`DataCollator` → 여러 개의 데이터를 묶어서(배치로) 모델에 넣을 수 있는 최종 숫자 형태(텐서)로 변환하는 역할


#### DataLoader
데이터 로더(Data Loader): 딥러닝 모델 학습 시 데이터를 효율적으로 묶고(Batch) 섞어서(Shuffle) 모델에 공급해 주는 핵심 소프트웨어 구성 요소
데이터셋을 배치 단위로 잘라서 순서대로(혹은 섞어서) 꺼내주는 역할
batch_size가 한 번에 몇 개씩 묶어서 학습할지를 정하는 숫자
batch_size=1 → 1개씩 학습. 그래서 뒤에 GRAD_ACCUM=4로 4번 모아서 한 번 업데이트하는 방식을 씀


#### fine-tuning
이미 학습이 끝난(사전학습된) 모델을 가져다가, 우리가 가진 200개의 문제-정답 데이터로 추가 학습을 시켜서 "이미지 4지선다 문제 풀기"에 특화되도록 만드는 단계
loss(오차)를 계산하고 모델 가중치를 업데이트
학습 끝나면 결과를 /content/qwen2_5_vl_3b_lora 폴더에 저장
Epoch 1의 train과 valid 진행
Epoch 2의 train과 valid 진행 

#### inference
학습이 끝난 모델을 실제로 사용해서 test 데이터의 정답을 예측
test.csv에 있는 문제들을 하나씩 모델에 넣고
모델이 생성한 답변 텍스트에서 extract_choice() 함수로"a/b/c/d 중 뭘 골랐는지 뽑아내고
그 예측값들을 모아서 최종 제출용 csv 파일로 저장

### 성능을 높이기 위해 시도해야 하는 것
1. 학습을 여러 번 반복
for epoch in range(1):
에서 숫자를 늘리면(range(3) 등) 같은 데이터를 여러 바퀴 반복 학습해요.
매 바퀴(epoch)마다 가중치가 조금씩 더 정답에 가까워지니까, 어느 정도까지는 성능이 올라가요.
너무 많이 돌리면 오버피팅 발생
valid_loader로 검증 손실을 매 epoch마다 찍고 있는 이유가 바로 이걸 감시하기 위해서예요. valid loss가 더 이상 안 떨어지고 오히려 올라가기 시작하면 그게 멈춰야 할 신호

2. 하이퍼 파라미터 수정
- 학습에 쓰는 데이터 양 늘리기 
train_df.sample(n=200, ...) -> 200개는 너무 적음

- 학습률 바꾸기 = 한 번에 가중치를 얼마나 크게 바꿀 것인가
lr=1e-4 -> 너무 크면 불안정, 너무 작으면 학습이 느림. 보통 몇 개 값을 실험해봄

- LoRA가 학습하는 파라미터 양 바꾸기
r=8, lora_alpha=16 -> r값을 키우면(16, 32 등) 표현력이 늘어나지만 과적합 위험 커짐

- 몇 스텝마다 가중치를 업데이트할지
GRAD_ACCUM=4 -> 배치 크기를 키우는 효과. 조정

- epoch 수 늘리기는 1번에서 설명

3. 성능 좋은 모델을 가져오기
지금 쓰는 Qwen2.5-VL-3B는 3B(30억 파라미터)급의 비교적 작은 모델이에요.
더 큰 모델(7B, 32B 등)을 쓰면 기본 성능 자체가 높을 수 있어요.
다만 모델이 커질수록 GPU 메모리도 더 많이 필요하고 학습/추론 시간 늘어남

4. 프롬프트 수정
좀 더 구체적으로 다듬으면(예: "이미지를 자세히 관찰하고, 각 보기를 하나씩 비교한 뒤 답하세요" 같은 지시 추가) 모델이 이미지를 더 꼼꼼히 보고 답하게 유도할 수 있어요.
코드 수정 없이 텍스트만 바꾸면 되니 가장 시도하기 쉬운 방법이기도 해요.

5. 모델을 바꾸기
MODEL_ID = "Qwen/Qwen2.5-VL-3B-Instruct"
에서 최근 모델인 
MODEL_ID = "Qwen/Qwen3-VL-8B-Instruct"


#### 뭘 바꿨을 때 어디서부터 다시 실행해야 하나?
- learning rate, epoch 수, GRAD_ACCUM → fine-tuning 셀부터만 다시
- 프롬프트 → 프롬프트 셀부터 다시 : 프롬프트가 바뀌면 데이터셋을 만드는 방식도 바뀜
- LoRA 설정(r, alpha) → 모델, Processor 셀부터 다시 : LoRA는 모델 구조 자체에 붙는 설정이라, 모델을 다시 만들어야 함
- 학습데이터 개수 → 라이브러리, 데이터, 설정 셀부터 다시 : 데이터 자체가 바뀌므로 그 뒤 전부 영향받음
- 모델 자체 → 처음부터


#### 클로드의 실험 제안 
데이터 개수 1000 / 에포크 3 / 학습률 1e-4 
데이터 개수 1000 / 에포크 3 / 학습률 5e-5 
데이터 개수 1000 / 에포크 3 / 학습률 2e-4
데이터 개수 1000 / 에포크 2 or 3 or 4 / 학습률은 앞에서 찾은 최적값으로
데이터 개수 5000 / 4차에서 찾은 최적값 / r=16과 lora_alpha=32
