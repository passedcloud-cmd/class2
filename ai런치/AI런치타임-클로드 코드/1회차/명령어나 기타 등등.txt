## CLAUDE.md
프로젝트 폴더 맨 위(루트)에 두는 **"이 프로젝트에 대한 설명서"**예요. Claude Code는 세션을 시작할 때마다 이 파일을 자동으로 먼저 읽어요.

여기에는 이런 걸 적어두면 좋아요:
- 이 프로젝트가 뭘 하는 프로젝트인지 (예: "학생 성적 관리 웹앱")
- 어떤 기술/언어를 쓰는지, 폴더 구조가 어떻게 되어있는지
- 지켜야 할 코딩 규칙 (예: "함수 이름은 영어로, 변수명은 카멜케이스로")
- 과거에 겪었던 실수나 주의사항 (예: "이 API는 초당 5번 이상 호출하면 에러남")

### CLAUDE.md 경로

내프로젝트/
├── CLAUDE.md          ← 여기! .claude 폴더 안이 아님
├── .claude/
│   └── skills/
│       └── prd_features/
│           └── SKILL.md
├── src/
└── package.json

| 종류 | 경로 | 적용 범위 |
| --- | --- | --- |
| 프로젝트용 | 내프로젝트/CLAUDE.md | 이 프로젝트에서만 |
| 전역용 (개인 취향) | ~/.claude/CLAUDE.md (홈 폴더) | 모든 프로젝트에서 (예: "설명은 항상 초보자도 이해하게 해줘" 같은 개인 성향) |

### 2. PR을 매번 만들고 merge할 필요는 없어요

작업 중간중간 확인하고 싶으시면 merge 없이도 바로 볼 수 있는 방법이 있어요.

- 웹 화면(claude.ai/code)에서 실시간으로 확인: 세션을 열어두면 Claude가 어떤 파일을 바꾸고 있는지, 추가/삭제된 줄이 얼마나 되는지(diff)를 실시간으로 볼 수 있어요. PR을 만들거나 merge할 필요가 없습니다.
- 직접 실행해보고 싶다면: merge까지 갈 필요 없이, Claude가 push해둔 브랜치만 pull(또는 checkout) 하면 돼요.
git fetch origin
git checkout <claude가-작업한-브랜치명>
이렇게 하면 merge 안 해도 그 브랜치 상태 그대로 로컬에서 실행/테스트할 수 있어요. merge는 "이 변경을 진짜 메인 코드에 최종 반영하겠다"고 결정했을 때만 하면 됩니다.

### 3. 더 편한 방법: --teleport

로컬에 Claude Code(터미널)가 설치되어 있다면, 아래 명령 하나로 클라우드 세션을 통째로 로컬로 가져와서 이어서 볼 수도 있어요.

bash
claude --teleport

1)터미널에서 claude --teleport 실행
이미 진행 중이거나 완료된 클라우드 세션 중 어떤 것을 가져올지 목록에서 고릅니다.
2)브랜치와 대화 기록이 그대로 로컬로 이동
Claude Code가 해당 브랜치를 자동으로 가져와서 체크아웃합니다. 대화 기록도 그대로 따라옵니다.
3)로컬에서 바로 실행해보기
merge 없이 바로 내 컴퓨터에서 실행/테스트 해볼 수 있고, 필요하면 이어서 직접 수정할 수도 있습니다.
